| 注入点 | 期望 | 证据 |

## 验证中发现并修复的缺陷（本阶段台账）

1. **预算拒绝事件随回滚丢失**：`reserve_budget` 在事务内先写 `budget_refused` 事件再返回 Err，整事务回滚使事件不落库。
   修复：预算拒绝改为已提交结果（`{"budget_refused": true, "reason"}`），请求不注册、实例保持 READY；
   控制面测试断言事件持久与相位。回归：`budget_gate_reserves_settles_and_releases`。
2. **批准后派发永久阻塞**：派发命令 id 固定为 `dispatch-{operation_id}`，首次 APPROVAL_REQUIRED 结果作为命令回执留存，
   用户批准后相同 id 重放旧回执，永远进不了 DISPATCH_COMMITTED。修复：派发命令 id 每次唯一，
   幂等锚回到操作状态机（"not dispatchable"/"lost the dispatch race" 重读继续）；
   APPROVAL_REQUIRED 分支转入等待（approve/deny 唤醒），消除热自旋。回归：`shell_approval_blocks_then_allows_and_denial_cancels`。
3. **runner spawn 失败驱动静默死亡**：`client::spawn` 2 秒未就绪返回 Err 经 `?` 传播使驱动任务退出，
   操作卡 DISPATCH_COMMITTED 无任何事件（真实模型验证首跑即复现：示例二进制无 jobs-runner 子命令，
   runner 即刻退出）。修复：无 journal 才 spawn（READY 未落盘=命令未启动，A14），spawn 失败以
   started=false/class=spawn 的 FAILED 回执关单；恢复臂对 READY journal 重发 GO（原 GO 可能随旧 runner
   丢失，A10 重复 GO 幂等），respawn 失败下拍重试不致命。回归：`v2_spawn_failure` + 驱动 7 项。

## 边界与未验证项

- ponytail：会话以固定权限快照运行（grant_revision=0），运行中权限变更的修订递增与再授权属后续；
  恢复时请求体从持久上下文按同一 request id 重建（响应未落盘前崩溃的情形），而非从请求制品复原。
- 已知天花板：job.json 的 token 与同 uid 的 shell 命令同信任域（单机单用户，D-41 主机 Shell 已含该假设）；
  跨容器/microVM 隔离后端不在本阶段，后端抽象点=JobSpec 协议+输出回传。
- 多实例生命周期/授权/委派/调度（R13–R16，P3）、MCP/Skills 与其余供应商（R17/R18，P4）、
  TUI 重连与干预（R19，P4）均未开始；旧产品循环与 Codex 后端保持可工作直至 P7 切换。
- A/B 正式性能实验未开始（P6）；本记录的三个真实任务证明持久化路径可工作，不构成成功率结论。
