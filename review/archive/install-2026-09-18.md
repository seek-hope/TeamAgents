## 交付

- GitHub 仓库 `seek-hope/TeamAgents` 已改为 public，API 回读为 `private=false`。
- `install.sh` 自动解析最新版、下载选定发行包、校验 SHA-256、安装两个程序；支持 curl / gh、
  指定版本、安装目录及不联网的本地安装。替换失败回滚旧程序，不覆盖配置和会话。
- Rust `teamagents init` 使用内置最小模板、XDG 路径和 `0600` 权限；保留已有文件和符号链接。
  默认 DeepSeek Flash / max / 1,000,000 上下文，密钥只引用环境变量。
- `doctor` 修正缺配置、不可读配置、空密钥的漏报；可选 Codex 能力标 WARN。
  `--help` / `-h` 和 `--version` / `-V` 可正常退出，不创建会话。
- 安装指南、README、发行说明同步；发行包带文档、示例和安装脚本，构建校验 crate/tag 版本一致性，
  使用锁文件，并对实际打包产物执行安装与 init 冒烟。

## 真实下载与本地制品

仓库公开后，用 PATH 中返回失败的 `gh` 替身强制安装器走 curl，真实执行了最新版解析、下载、
SHA-256 校验、安装及 `version`：线上 `v0.1.1` 全部通过，缺配置时按兼容逻辑创建模板。
没有模型 API 调用，也没有改写本机用户配置或安装目录。复跑方式：

```bash
install_check_dir="$(mktemp -d)"
mkdir "$install_check_dir/tools"
printf '#!/bin/sh\nexit 1\n' > "$install_check_dir/tools/gh"
chmod +x "$install_check_dir/tools/gh"
PATH="$install_check_dir/tools:$PATH" XDG_CONFIG_HOME="$install_check_dir/config" \
  sh install.sh --bin-dir "$install_check_dir/bin"
XDG_CONFIG_HOME="$install_check_dir/config" "$install_check_dir/bin/teamagents" version
```

本次还用当前 engine/TUI 的本机 debug 二进制组装临时发行包，经过实际安装器安装后，
两次 `init` 均退出 0，生成内容与内置模板一致，第二次保持文件不变，安装后的两个二进制与源文件一致。
本机只安装了 GNU Rust target，**没有本地重建新版 musl 制品**；新版 musl 构建与其打包冒烟由发布工作流执行。

## 回归中发现的测试竞态

完整 engine 回归最初在 `process_leaks` 两项测试出现 `initialize timed out`，单独重跑也复现 MCP 超时。
假服务原先启动即写响应，存在先于 pending request 注册到达的竞态；运行时丢弃无对应请求的响应是预期行为。
现让假服务先读取初始化请求，再回复错误，仍保留“子进程必须被回收”的原断言。
定向复跑两项通过，耗时约 0.1 秒；本次未改动 Codex/MCP 产品实现。

## 发布边界

仓库可见性变更已经生效。安装器和文档随本批代码合入 main 提供，源码提交不等于创建新版二进制发行。
本次验证时线上最新版为 v0.1.1；安装器兼容该版本，新版 init/doctor 仍需通过后续发行工作流提供。
真实服务兼容性验收不由这些安装与回归检查替代。

## 发布前 CI 测试修正

首次远程 CI 的 `doctor_fresh_install_and_optional_codex` 失败：测试将 bwrap 替身放入 PATH，
但隔离执行会使用固定的沙箱 PATH，因此实际运行的是宿主机 bwrap，本机通过不能保证 CI 通过。
现以空 PATH 明确模拟缺少 bwrap 与 Codex，断言有效模型配置下只有必需的 bwrap 报 FAIL，
可选 Codex 报 WARN；缺配置、空密钥与不可读配置的断言保留。此次仅修正测试，不改隔离实现。
定向复跑 `cargo test --offline --locked --manifest-path engine/Cargo.toml --test cli`：4 项通过。

后续 CI 35327829061 在 `model_overrides_survive_session_reopen` 报持久化目录不存在。
该测试文件的 4 项用例并发改写进程级 `XDG_STATE_HOME`，会使会话打开与后续写入使用不同的目录。
现按现有 `chat_e2e` / `codex_contract` 的方式，用同一互斥锁保护这 4 项测试的完整生命周期；
产品代码及回归断言保持不变。本机修复前连续 10 次未复现，失败证据来自上述远程 CI。
修复后运行 `cargo test --offline --locked --manifest-path engine/Cargo.toml --test model_override -- --test-threads=4`
连续 10 次均为 4 项通过。
