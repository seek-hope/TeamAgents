# review: reviews, evaluations and evidence

This directory holds **re-runnable checks and their raw evidence**. Conclusions need a command or a probe, and
tests are recorded separately from evidence.

| Path | Contents |

| [`dsec-kernel-reference-2026-09-24.md`](dsec-kernel-reference-2026-09-24.md) | notes comparing an external sandbox platform with this kernel design |

| `citations.py` | check every backticked citation in the tracked markdown against the tree: a cited qualified name and a repository-looking path must resolve, or the line must record the thing as removed — part of `make check` through `make hygiene` (the detector behind D-110) |
| `decisions_log.py` | check the shape of the binding decision log (`docs/DECISIONS.md`): one heading per entry matching `## D-<n> <title> (<YYYY-MM-DD>)`, strictly newest-first, each followed by a body — part of `make check` through `make hygiene` (the detector behind D-107) |
| `nobwrap_path.py` | build a `PATH` that holds every tool except `bwrap`, i.e. the GitHub runner's condition, so `make check-nobwrap` runs the whole gate the way CI does (`--verify` asserts the farm really lacks `bwrap` and has `sh`/`python3`/`cargo`/`make`) — the reproducible condition behind D-113; `--stub-bwrap` writes a `bwrap` stub that dies like Ubuntu 24.04's AppArmor restriction does, which `make check-broken-sandbox` runs the gate in (D-114) |
| `silent_skips.py` | report a `#[test]` whose `if <condition> { return; }` guard says nothing — a silent skip that makes the test a no-op (guards inside a test's own helper or a `tokio::spawn` are not skips) — part of `make check` through `make hygiene` (the detector behind D-121) |
| `command_params.py` | compare every control command's payload fields with the fields the command layer reads, per method — a field the engine fills in and nothing reads is dropped silently (D-124; it reproduces D-123's `error_class` exactly) — part of `make check` through `make hygiene` |
| `event_catalogue.py` | keep `docs/EVENTS.md` equal to the `event(...)` call sites in `core/src`: a kind emitted but undocumented, a documented kind that no longer exists, a changed payload key or a stale table fails (the readers column is derived) — part of `make check` through `make hygiene` (D-125) |
| `protocol_catalogue.py` | keep `docs/PROTOCOL.md` equal to the daemon's dispatchers: every read method and every control command, with the parameters its handler reads, whether an identity is checked, and the dispatch site (part of `make check` through `make hygiene`, the detector behind D-126) |
| `tool_catalogue.py` | keep `docs/TOOLS.md` equal to the three tool-schema functions: every tool a model may be offered, its parameters (required marked) and its model-facing description (part of `make check` through `make hygiene`, the detector behind D-127) |
| `dead_code.py` | list every public item no caller anywhere mentions (crates, tests, examples and the CLI-driving scripts; prose in docs is not a use), with the known-uncalled items and their reasons listed separately — the audit behind D-78 and D-86 |
| `runner_cost.py` | measure what one running command costs the machine: the runner's tick and the driver's `status` poll at the cadences the code uses (and the ones it used to), as a re-runnable table (no model, no daemon) — the measurement behind D-116 |
| `install_check.py` | verify the documented install path end to end: the published release downloads, its SHA-256 matches, `install.sh` installs both binaries and they run, and a corrupted archive is refused without touching an existing installation (needs network and a published release; not part of `make check`) |
| `tmp/` | ignored probe and scratch area (never committed) |

Reviews from earlier implementations and their migration are no longer in the tree; they stay reachable
through Git history (`git log -- review/archive`) and do not describe the current code. Current behaviour is
defined by [`docs/DESIGN.md`](../docs/DESIGN.md), [`docs/USER-GUIDE.md`](../docs/USER-GUIDE.md) and
[`docs/ACCEPTANCE.md`](../docs/ACCEPTANCE.md). A read-only review never modifies the reviewed files, and a
falsification claim must first rule out probe error.
