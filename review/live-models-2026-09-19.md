# 真实 Chat 模型矩阵入口（2026-09-19）

在方案 §11、T7/T19 与 D-32/D-35 授权范围内新增 Rust 验收入口，没有修改生产模型适配器、
权限策略或持久化格式。此前各协议有本地回归，但缺少统一的、有原生窗口约束的真实冒烟入口。

## 入口与判定

`engine/tests/live_models.rs` 的真实入口用 `#[ignore]` 标记，必须显式指定清单、证据目录及可用凭据。
TOML 的每个条目绑定 profile、精确模型名、原生窗口与来源；配置中已有窗口不得冲突，
未配置时才取清单声明。模型、档位、超时、重试和其他选项保留；报告记录原始及有效 profile 指纹。
来源由执行者核实，入口检查非空和配置一致性，不声称能自动核实模型原生窗口。

只导入选定的模型 profile，生产会话运行于独立工作目录及 XDG 配置/状态。
工具使用既有 files/Shell，Shell 仍在 bubblewrap 中运行。无其他配置中的 MCP、hooks、
Skills、指令文件或项目输入。RAII 先关闭运行时、等待其工具收敛，再释放测试环境。

每个模型独立执行三个阶段：

1. `read_file` 读取随机输入，用 `write_file` 复制并读回核对；输入不变。
2. 驱动移除第一阶段的输入和输出，检查工作目录为空；同会话从历史恢复随机值，用 Shell 写新文件并读回。
3. 驱动移除第二阶段输出并确认工作目录为空，关闭并销毁会话对象，再打开相同会话；先检查用量账本一致，
   再从私有历史恢复随机值，写文件并读回。

驱动直接核对精确文件内容和普通文件类型，同时检查实际成功工具回执、新回合均为 COMPLETED、
最终标记及新增用量。模型声称成功不能替代这些断言。报告只存状态、计数、断言与指纹，
不存原始模型文本、工具参数、服务错误正文或任意生成参数；中断时已有阶段报告保留。
缺 profile/密钥记 skipped，窗口或模型不一致记 blocked，任务行为失败记 failed。
有任何未通过条目时命令非零退出，不能把 Cargo 的跳过当真实通过。

## 离线验证

五项自动化契约随 `make check` 运行：

- `manifest_and_profile_checks_refuse_unknown_or_conflicting_windows`：拒绝空清单、重复配置、
  未知或冲突窗口、缺来源、模型漂移和空凭据；显式补全窗口不更换其他 profile 字段。
- `matrix_preflight_is_incomplete_and_preserves_safe_evidence`：无配置/凭据不启动模型，
  报告持久化为 incomplete，敏感端点、任意选项和用户扩展不进入报告或运行 catalog。
- `matrix_contract_streams_files_continuation_and_cold_history_for_every_protocol`：
  本地 SSE 服务逐个验证 openai、deepseek、responses、anthropic；真实文件及 bubblewrap Shell，
  关闭重建后的实际请求仍含旧历史，DeepSeek 保留推理字段；每模型 10 请求、80 个夹具 token。
- `matrix_contract_rejects_false_success_and_retains_sanitized_failures`：只有成功文字却没文件、
  以及 HTTP 401 都失败并保留结构化报告，服务正文不泄露到报告。
- `matrix_contract_rejects_leftover_files_as_history_evidence`：第一阶段文件正确但留下额外文件，
  仍判失败且不启动续接，防止用另一份文件替代历史恢复。

本机完整验证：core **84**、engine **312**（另 **3 ignored**）、TUI **104**；
格式、严格 Clippy、仓库卫生检查通过。`check-runner.sh` 原有 **30** 项契约通过。
没有生产或 TUI 行为变更，本批未重跑 PTY。

## 真实执行与边界

复用上一批冻结配置，未修改用户当前配置文件：
DeepSeek Flash / deepseek / 原生 **1,000,000** / high / 请求超时 **120 秒** / 重试 **5 次**。
原生窗口来源为 D-36 的用户确认；阶段时限 600 秒。

2026-09-19 的首次新会话三阶段均通过，总耗时 **12.828 秒**，**11** 次模型请求；
累计输入 **54,314**、输出 **1,583**、合计 **55,897 tokens**，缓存输入 **48,512**，
未知用量请求 **0**。模型执行了 **7 次成功工具调用、1 次失败调用**：
第一阶段多发了一次无效 `complete_task`，随后继续完成任务。报告保留该失败，不描述为零错误运行。
三次文件断言、初始输入不变及关闭重开后的用量一致性全部通过。

复核后增加“续接前工作目录为空”的断言与反例，以防额外文件绕开历史恢复。
最终入口用同一模型配置另开新会话复跑：三阶段通过，**14.933 秒**、**14** 次请求；
输入 **69,301**、输出 **1,567**、合计 **70,868 tokens**，缓存输入 **66,048**，
未知用量请求 **0**；**11 次成功工具调用、0 次失败**。两次空目录断言与恢复用量一致性通过。
首跑保留，但其入口尚无空目录断言，不把两次不同验收器版本合并成相同条件的完成率。

另一次仅用于验收入口的缺密钥反例写出 `incomplete/skipped`，Cargo 退出 **101**，
没有启动模型请求。它不是失败的真实供应商样本。
