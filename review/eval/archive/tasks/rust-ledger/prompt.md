约定如下：

1. 金额内部为 `i64` 分。`parse_cents` 接受首尾空白、可选负号、至少一位整数，以及可选的 1 或 2 位小数；例如 `-0.01`、`12`、`12.3`。不接受正号、指数、非数字、空整数、空小数或超过两位小数。全程精确转换，支持 `i64` 分的完整范围，溢出必须返回错误，不能截断、舍入、饱和或 panic。`format_cents` 对完整范围输出两位小数，负数必须保留负号，两函数应能往返。
2. 流水是无引号、逗号分隔的 UTF-8 文本，支持 `deposit,请求ID,账户,金额` 与 `transfer,请求ID,源账户,目标账户,金额`。每个字段去除首尾空白；忽略空行与去除首尾空白后以 `#` 开头的整行注释。不支持表头、行内注释或额外列。请求ID、账户只能包含 ASCII 字母、数字、下划线和连字符，且不能为空。每笔金额必须大于零。任何非法行都返回错误，错误以 `第 N 行：` 开头，N 是原输入中从 1 开始的物理行号。
3. `Ledger::apply` 也必须独立校验传入的 `Event`，不能只依靠 CSV 层。存款可创建账户；转账要求两端账户已存在且不同、源账户余额充足、目标余额无溢出。余额始终是非负的 `i64` 分。非法事件返回错误，账本与请求记录都不改变。
4. 请求ID全局唯一。首次成功应用返回 `Ok(true)`；相同ID且内容完全相同的成功请求重放返回 `Ok(false)`，不重复修改余额；同ID不同内容返回错误。失败请求不占用ID，修正余额或内容后可以用同一ID重试。失败的转账不能只扣款或创建账户。
5. 库入口 `run` 和命令 `cargo run --offline --quiet` 都从完整流水生成报表：按账户名排序，表头使用已有 `user_policy::REPORT_HEADER`，随后每行 `账户,两位小数金额`，末尾换行。CLI 从 stdin 读取；任何解析或记账错误都必须令 CLI 非零退出，stderr 有错误信息且 stdout 为空，不能输出部分报表。重复成功请求不影响报表。
