# rust-ledger 仓库任务

该任务衡量单个 coding agent 在需求明确、公开样例不足时，对多文件缺陷的定位、修复和验证能力。纯标准库 Rust 项目包含金额、流水解析、账本、库入口、CLI 和用户定制六个源文件；公开测试故意只覆盖正常路径。它是复杂仓库评测的起点，不代表大型仓库或数小时任务验收。

主要缺陷互相影响：浮点金额丢精度及负数输出错误；输入校验和物理行号错误；请求幂等冲突与失败记录处理错误；转账先扣款及余额溢出；库入口吞掉记账错误。提示词给出全部业务约束，隐藏测试没有额外的未声明要求。

评测时只复制 `fixture/` 给模型。`checks.txt` 是模型可见的基础检查；`hidden_tests.rs` 在模型退出后由可信评分器注入独立副本的 `tests/hidden.rs`。`allowed-files.txt` 仅允许修改五个既有源文件；Cargo 清单、锁文件、公开测试和 `src/user_policy.rs` 必须字节不变。`grade.json` 是评分器的运行产物，不是任务输入。

任务构建时已验证：

- 原始 fixture：`cargo test --offline --quiet`，3 个公开测试全部通过。
- 原始 fixture 注入隐藏测试：`cargo test --offline --all-targets`，3 个公开测试通过、11 个隐藏测试全部失败，退出码 101。
- `/tmp` 中的独立参考修复：同一命令下 3 个公开测试与 11 个隐藏测试全部通过。参考答案未写入任务目录。

隐藏测试覆盖精确十进制和完整 i64 范围、格式往返、语法拒绝、物理行号、直接 API 校验、重放与冲突、失败重试、转账原子性、溢出无副作用、用户表头、排序及 CLI 失败时 stdout 为空。以上是测试集有效性证据；真实模型完成率由独立运行记录报告，不能由参考修复通过推断。

复跑原始负例可将 `fixture/` 复制到新临时目录，再将 `hidden_tests.rs` 复制为其 `tests/hidden.rs`，执行上述离线 Cargo 命令。不要把隐藏测试复制到真实评测的模型工作目录。
