# 多文件 Rust 仓库真实模型评测（2026-09-17）

本轮按照 D-36 使用 DeepSeek Flash 的原生 **1M** 上下文（用户确认；配置值 1,000,000）。任务文件、模型、二进制与评分器固定，清单见 [manifest.json](manifest.json)。

**完整任务成功 2/3；三份候选代码均通过隐藏 11/11、公开测试及文件保护检查。** 第 2 次到达任务时限，仍计失败。未运行竞品，不能据此推断通用工程成功率或排名。

## 条件与评分

- 模型 `deepseek-flash`，DeepSeek 协议，`reasoning_effort=max`；单请求超时 120 秒，任务上限 600 秒，模型步数上限 200，full-auto。
- 三次独立运行使用全新工作区和状态目录，并发启动，共享供应商吞吐。用户配置未修改；凭据由原有环境变量读取。
- `rust-ledger` 是构造的六文件 Rust 仓库：五个允许修改的源码文件，三个公开测试，十一个隐藏测试。它不是大型开源工程的代表样本。
- Agent 退出后，在单独的可信副本中执行隐藏和公开测试；保护 Cargo 文件、公开测试与用户定制文件，拒绝额外文件与符号链接，候选代码只在无网络 bubblewrap 中运行。
- 完整成功须同时满足 Agent `completed` / exit 0、公开验收通过、隐藏评分通过及保护检查通过。代码通过测试但 Agent 超时，仍计任务失败。

公开基础测试不能检出原始全部缺陷：原始代码公开 3/3、隐藏 0/11；独立参考修复公开 3/3、隐藏 11/11。该正反例只用于验证评分器有效性。

总耗时包括 CLI 验收及结束清理。第 3 次的 `goal_done` 实际在首个回合启动后 **599.620 秒**产生，CLI 随后正常返回 0。第 2 次在约 226 秒时发生成员模型响应超时；Leader 重派后，实现与验证任务成功，但 Leader 未在总时限内完成收尾，最终为 timeout / 124。

输入/输出 tokens 是所有成员、所有已记录调用的累计值，**不是单次上下文占用**；累计输入超过 1M 不表示超出原生上下文。输出包含供应商报告的推理用量，中断请求的完整用量可能不可得。所有实际调用成员的 `context_window` 均核对为 1,000,000；三次均未产生压缩摘要节点。因此本组验证多文件任务及协作闭环，压缩算法的正确性仍以独立本地回归为证。

第 1 次的工具失败是同一 `edit_files` 请求对同一文件提供多条编辑；第 3 次为原生文件工具尝试写工作区之外。两项均被拒绝，后续完成任务。三次均只修改五个允许的源码文件，Cargo 文件、公开测试及用户表头逐字节不变。

## 复跑

临时配置中令 `models.leader_main.context_window=1000000`，其余模型设置保持以上值，凭据从原有环境变量读取：

```bash
cargo build --offline --manifest-path engine/Cargo.toml --bin teamagents
XDG_CONFIG_HOME=/path/to/temporary/config-root \
  review/eval/run.sh --only rust-ledger --timeout 600 --out /tmp/teamagents-ledger-new-run
```

每次使用独立输出目录。测试其它模型时先核实其原生上下文长度，并记录来源。少量单任务重复不能证明通用完成率或竞品排名。
