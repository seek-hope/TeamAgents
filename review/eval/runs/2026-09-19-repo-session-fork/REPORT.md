# 真实历史仓库任务：三次独立运行（2026-09-19）

固定 `repo-session-fork` 任务的完整成功率为 **0/3**。两份候选的允许源码在补充诊断中
通过隐藏与公开检查，但原始尝试仍有超时、额外文件或退出码失败，不能算成功。
第三轮暴露了一处真实 CLI 判定缺陷，已在批次归档后修复；没有重写本报告的原始成绩。

## 条件与校准

输入来自 TeamAgents 提交 `046a43e32a73794e057ae0331ee3247ee3c42179`，包含 3 个 crate、
77 个文件、58 个 Rust 文件、29,285 行 Rust。仅允许修改 `engine/src/worker.rs` 和
`engine/src/session.rs`，其余输入内容及常规权限位保留；固定清单中的 `target/` 构建目录除外。
旧测试所需的无凭据配置作为显式输入提供。模型看不到 Git 历史、`review/`、隐藏检查或参考答案。

使用 DeepSeek Flash / high / 原生 **1,000,000** 上下文，长度来源为用户确认的 D-36；
请求超时 120 秒、最多重试 5 次。每次使用全新工作区和会话，顺序运行，任务时限 1200 秒。
模型可以自行组队，用量按全部成员累加；默认回合步骤上限与 16,000 字节旧结果遮蔽预算不变。
保留原生文件边界及无网络 bubblewrap。任务源码的编译和测试均在该隔离内运行。

## 已修复的 CLI 判定缺陷

[第三轮最终状态](sample-3/cli-state-probe.json)包含同目标的一条旧 `FAILED`、
三条 `COMPLETED`，无待批准，`goal_state="done"`；原始 JSONL 中还有 `goal_done` 和最后
`run_completed`。`cli.rs::exec_outcome` 原先在权威目标状态之前检查任意历史失败，
使恢复后完成的执行仍返回 1。

归档后调整优先级：超时、待批准和 `OUTCOME_UNKNOWN` 继续阻止成功；
目标已提交完成且验收通过时，历史失败只作为审计记录。目标未完成或检查失败仍非零。
没有删除失败记录或放宽 core 完成条件。

[修复前回归](exec-before.log)实际复现 failed/1，
[修复后回归](exec-after.log)通过，含超时、批准、未知结果和失败检查的负例。
[补丁](exec-outcome-fix.patch)及[修复后源码哈希](exec-fix-hashes.json)单独保存。
修复后没有再次调用真实模型；它不能抹掉这组三轮的文件范围失败或反推新的成功率。

## 工程验证与复跑

评测冻结前 `make check` 为 core 84 / engine 302 / TUI 104；
CLI 修复后为 **core 84 / engine 303 / TUI 104**，engine 另 2 个显式 ignored 入口。
格式、全部目标 Clippy `-D warnings`、测试与仓库卫生通过。
runner 最终 30 项契约通过，其中新增了严格 umask 下输入复制权限的检查。
三轮使用启动时冻结的 runner；之后的 `cp -pR` 修复只影响旧目录 fixture，不影响本任务的
Git 准备路径，见[冻结脚本](runner-frozen.sh)、[差异](runner-final.patch)、
[修复前误判](runner-umask-before.log)与[最终契约检查](runner-check-final.log)。

```bash
XDG_CONFIG_HOME=/path/to/isolated/config \
review/eval/run.sh --bin /path/to/frozen/teamagents \
  --only repo-session-fork --out /tmp/new-repo-session-fork-run
```

`timeout.txt` 固定 1200 秒。模型配置必须保持原生上下文；本组 DeepSeek Flash 为 1,000,000。
每个 `sample-N/` 保存原始 JSONL、stderr、退出记录、runner/评分日志、候选补丁、
最终文件清单、指标与读取诊断；补充评分另有明确文件名。
归档前扫描了当前凭据值，并核对冻结源码、二进制、任务、评分器与配置哈希。
完整指标见 [metrics.json](metrics.json)，校验日志见
[冻结前检查](make-check.log)与[CLI 修复后检查](make-check-after-exec.log)。

本任务是 TeamAgents 自身历史仓库，公开检查只有四个相关 suite；
不代表陌生第三方仓库、全仓库验收或通用编码排名。文件保护只验证最终候选，
不证明过程中从未临时创建、改动或删除其他文件。本批没有运行 Codex CLI、Claude Code、
pi 或 Hermes 作同任务对照，长期成熟度目标仍未达成。

输入裁剪还有一项具体限制：未包含 `review/tmp/parity_scenario.json`，而旧版 TUI 的
`render_tests.rs` 会读取它。模型自行扩大测试时遇到了这一缺失；相应耗时不能全部归因于
运行器效率。后续扩展完整仓库验收应补齐合法的公共测试数据并单独版本化，
不在本批运行后修改输入或追改成绩。
