# R2-P1 小型 kernel 本机记录

日期：2026-09-23。范围：R05 薄协议适配与 DeepSeek、R06 同 kernel 直驱参考、R07 基础工具与结构化回执、R08 完整轨迹/用量。
结果：确定性单测、假服务契约测试、编排端到端、新旧对照全部通过；3 个真实 DeepSeek 任务在参考循环上完成。
参考循环是评测组 A 的直驱参考（RV-38），不带生产恢复承诺；持久化执行位置、多实例、MCP/Skills、其余供应商不在本阶段。

## 交付物

| 交付 | 位置 | 说明 |
|---|---|---|
| kernel | `core/src/kernel/` | 无 I/O 状态转换：`prepare_request / interpret_response / apply_observation`；finish 唯一完成申请、read_history 回读、L1 视口掩码、窗口估算（沿用旧契约） |

| 直驱参考 | `engine/src/reference.rs` + `engine/examples/rebuild_p1.rs` | 同 kernel 的无组队任务循环：步数/时限有界、一次性完成申请、readback、逐事件轨迹 |

## 确定性证据（全部离线）

- core kernel 单测 9 项：请求构造、意图下标与 args 散列、纯回复不结清、唯一 finish 完成申请、finish 混排忽略+提示、非法参数保留、掩码与回读配方、分页契约、双供应商 usage 形状。
- 假 HTTP 服务契约 7 项（`engine/tests/providers_fake.rs`）：SSE 组装 reasoning/tool_calls/usage、非 SSE 回退、429/500→Transient、400 上下文→ContextOverflow、401→Permanent、可见输出前/后截断分别 Transient/Permanent、取消放弃读取（<5s 返回）、文本预览事件。
- 参考循环端到端 5 项（`engine/tests/rebuild_p1.rs`，脚本供应商）：工具执行+完成、readback 分页 30,013 字符信封、纯回复终止、Transient 一次重试权属、步数预算有界。
- 新旧对照 1 项（`engine/tests/rebuild_p1_compare.rs`）：同一罐装响应驱动旧 ChatRunner 与新 kernel。两侧均为 chat-completions 线形（model/messages/tools/stream）；基础工具两侧齐备；旧路径团队工具与新内建 finish/read_history 为已记录设计差；**同一 shell 命令的工具结果以完全相同的 `{"output": ...}` 内容进入两侧第二轮请求**，assistant 轮保留同一 call_id。
- 门禁：`make check`（rustfmt、严格 Clippy、三 crate 离线锁定测试、仓库卫生）与 `make pty` 全绿；旧产品测试未删改。

## 真实模型证据（DeepSeek Flash，原生 1M 窗口）

复跑（需 `DEEPSEEK_API_KEY`，网页任务另需 `ANYSEARCH_API_KEY`）：

```bash
cargo build --offline --manifest-path engine/Cargo.toml --example rebuild_p1
engine/target/debug/examples/rebuild_p1 --task-file <brief> --workdir <dir> --trace <dir> [--web] [--effort high]
```

| 任务 | 结果 | 证据 |
|---|---|---|
| 计算 17*23 写入 answer.txt 并 cat 验证 | completed/success，3 步，5,541 tokens | `review/eval/runs/2026-09-23-r2-p1-reference/result1.json`、`trace1/run.trace.jsonl` |
| seq 1 5000 掩码输出，read_history 翻页到 EOF，写 tail.txt | completed/success，7 步；模型自行翻页至 `eof=true`（total_chars=28,936），diff 校验一致 | `result2.json`、`trace2/`、`tail.txt`=4996..5000（同目录归档） |
| 网页搜索当前 SQLite 稳定版 + 抓取 wal.html | completed/success；sqlite-version.txt=3.53.4，引用下载页与年表两处独立来源 | `result3.json`、`trace3/`（同目录归档） |

真实运行期间出现一次供应商侧传输中断（curl 同时复现 TLS EOF）：参考循环按一次性重试权属记录 6 次尝试后如实失败（`result2.json` 第一次运行的 run_end），无重复计费争议之外的隐式行为；恢复后重跑成功。这证明的是失败记账路径，不是 API 稳定性。

## 边界与未验证项

- 参考循环不承担恢复承诺：进程崩溃不续跑（R09–R12 在 P2）；轨迹是审计原件，界面预览与权威记录分离。
- 容量估算仍是保守文本估算（est 1,267 vs 实际 1,479 prompt tokens）；压缩策略与收益不在本阶段（R22/P5），窗口按原生长度构造。
- ureq 旧栈随旧 ChatRunner 保留，旧循环删除时一并移除；本阶段没有第三套 HTTP 栈。
- MCP、Skills、Anthropic/Responses 适配、多实例授权/通信、TUI 接入均不在 P1（R17/R18、P3、R19）。
- A/B/C 正式性能实验未开始（P6）；本记录不构成成功率结论。
