## pi-ai 多供应商设计对照（2026-09-24 调研，差距为待确认项，未落码）

仓库已迁至 `earendil-works/pi`（原 badlogic/pi-mono）。R17 已采纳的部分：
model.api 按协议路由、目录显式声明协议、凭据在配置边界解析、跨协议不转发旧原生块。
其余协议适配器（google/vertex/bedrock/mistral/azure/openrouter）是后续"需要哪个加哪个"的路标，
适配器模式已就位。以下差距按建议优先级排列：

| pi 的做法 | 出处 | 我们的缺口 | 建议 |
|---|---|---|---|
| 跨协议 tool call id 归一：Responses 的 id 有 450+ 字符含 `\|`，Anthropic 要求 `^[a-zA-Z0-9_-]{1,64}$`；用 toolCallIdMap 做同一原 id → 同一新 id 的一致映射 | api/transform-messages.ts | 同一实例 `/model` 跨协议切换后，旧上下文的 tool_call/tool_result id 原样转发会被 Anthropic 拒绝 | **优先补**：协议适配边界按请求内一致映射归一 id（R17 缺陷修补性质） |
