# TeamAgents repository conventions

- Maintain one root Rust crate and one `teamagents` binary. Read the [README](README.md) for commands and [current decisions](docs/DECISIONS.md) for the contract. Check `git status` before editing. The [architecture diagram](docs/architecture.canvas) shows how tasks run.
- Prefer the standard library and existing dependencies (including the minimal `ratatui`/`crossterm`/`unicode-width` TUI stack). Confirm design deviations before implementation and update the current rule in place. Interactive TTY `chat` and `tui` launch the TUI, while non-TTY I/O, `--json`, and `--plain` preserve the line-oriented client. Use English for code, user-facing strings, docs and commits except for `README.zh-CN.md`. Keep both READMEs aligned with CLI help.
- Use the pinned Rust toolchain and `Cargo.lock`. Run `make fmt` to format and `make check` before committing. CI requires format checks, Clippy with warnings denied and all tests, including sandbox tests. Provision `/usr/bin/bwrap`, `/usr/bin/slirp4netns` and working Linux namespaces. `make package` produces a local host binary archive.
- Keep tests isolated by workspace, session directory and child-process environment. Use a loopback fake for provider I/O and keep live credentials out of prompts, state and logs. Local tests establish neither live model quality nor production network isolation.
- New roots use a one-way execution tree. A handoff closes the sending stage and creates all its children atomically. Grow branches within the agent limit and one finite root model-call budget, including repair and summarizer calls. Children cannot send work to ancestors or siblings. Only the initial root stage can ask for clarification before acting. Support `answer ROOT_ID TEXT` and `/answer ROOT_ID TEXT`. Keep the final summarizer outside the execution tree with access to the original intent and leaf results.
- Preserve the single writer, separate histories and unknown-outcome boundary. New roots default to unattended execution in a network-enabled workspace. `--review` requires per-operation approval for model-requested edits and shell commands. Descendants inherit the root's policy. When opening a stored session, preserve each root's routing, approval policy and pending operations. Require per-operation review for stored roots that lack an explicit policy.
- Both shell tools and user checks use a staged workspace with validated publication. Preserve the file-mount boundary and private loopback. Keep model reports distinct from observed root and descendant evidence. A checked root can succeed only after the exact authorized command passes. Allow at most three attempts total within the shared budget, with repair moving forward to a new stage.
