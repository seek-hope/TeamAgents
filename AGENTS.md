# TeamAgents repository conventions

- Maintain one root Rust crate and one `teamagents` binary. Read the [README](README.md) for commands and [current decisions](docs/DECISIONS.md) for the contract. Check `git status` before editing. The [architecture diagram](docs/architecture.canvas) shows how tasks run.
- Prefer the standard library and existing dependencies (including the minimal `ratatui`/`crossterm`/`unicode-width` TUI stack). Confirm design deviations before implementation and update the current rule in place. Interactive TTY `chat` and `tui` launch the TUI, while non-TTY I/O, `--json`, and `--plain` preserve the line-oriented client. Use English for code, user-facing strings, docs and commits except for `README.zh-CN.md`. Keep both READMEs aligned with CLI help.
- Use the pinned Rust toolchain and `Cargo.lock`. Run `make fmt` to format and `make check` before committing. CI requires format checks, Clippy with warnings denied and all tests, including sandbox tests. Provision `/usr/bin/bwrap`, `/usr/bin/slirp4netns` and working Linux namespaces. `make package` produces a local host binary archive.
- Keep tests isolated by workspace, session directory and child-process environment. Use a loopback fake for provider I/O and keep live credentials out of prompts, state and logs. Local tests establish neither live model quality nor production network isolation.
- Opening `teamagents` defaults to a fresh session with isolated node histories; legacy tasks keep agent-keyed history while tree nodes never share history across sessions. New rounds use a one-way execution tree: a handoff closes the sending stage and creates up to 64 children atomically, with no session member cap, concurrency cap, same-agent serialization, or per-round turn budget. Active `Root` and `Node` workers may issue parallel single-turn tool batches (up to 16 calls per turn: read-only tools run concurrently, side-effecting tools run sequentially, while solo control ops `finish`/`handoff`/`ask`/`wb_wait`/`spawn`/`delegate`/`send` remain singleton). Workers discover hierarchical `AGENTS.md`/`AGENTS.override.md`, local `SKILL.md` indexes (`read_skill`), git/env context, native tools (`apply_patch` V4A diffs, `list_dir`, `grep_files`, `read_file` with optional `line_numbers`, `update_plan`), and `mcp.json` MCP servers (`mcp_list`, `mcp_call`). Children cannot send work to ancestors or siblings, while active sibling leaves may coordinate through the per-root collaborative whiteboard (`wb_read`, `wb_write`, deadlock-free `wb_wait`; inspected via `whiteboard`/`wb`, `/wb`, and the TUI `Board` tab). Only the active subtree root stage can ask for clarification before acting. Support `answer ROOT_ID TEXT` and `/answer ROOT_ID TEXT`, mid-turn `steer ROOT_ID TEXT`, manual `compact`, `diff`, `review`, `resume`, `--jsonl`, and TUI `@file` completion. A round with 1 terminal leaf settles directly at that leaf; 2+ terminal leaves converge into an in-tree summarizer node. User follow-up input sends directly to that sole leaf or summarizer and promotes it to the root of the next subtree round (`continue TASK_ID TEXT`) with per-round member uniqueness. Workers auto-compact long histories on overflow or soft byte pressure while reporters do not.
- Preserve the single writer, per-node isolated tree histories and unknown-outcome boundary. New roots default to unattended execution in a network-enabled workspace. `--review` requires per-operation approval for model-requested edits and shell commands. Descendants inherit the root's policy. When opening a stored session, preserve each root's routing, approval policy, sandbox mode (`direct`, `staged`, or `read_only`) and pending operations. Require per-operation review for stored roots that lack an explicit policy.
- Shell tools and user checks default to direct `bwrap` workspace-write isolation (hiding `.teamagents-auth` and mounting top-level Git admin dirs read-only); `--staged` / `--sandbox staged` opts into staged copy-on-exit with validated publication, and `--sandbox read-only` mounts the workspace read-only while disabling write tools (`edit_file`, `apply_patch`). Preserve the file-mount boundary and private loopback. Keep model reports distinct from observed root and descendant evidence, and treat whiteboard entries strictly as unverified collaborative notes. A checked root can succeed only after the exact authorized command passes. Allow at most ten attempts total, with repair moving forward to a new stage.
