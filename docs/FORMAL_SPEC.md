# Formal Specification and Verification Contract

`src/formal_tests.rs` explores bounded, hand-written state-transition abstractions with exhaustive BFS and runs a scripted integration scenario against the real SQLite `Store`. This is useful model checking and integration evidence, but it is **not** a refinement proof of the production implementation: the models omit production paths (multi-level handoff, 64-child limits, member uniqueness, summarizer inputs, most whiteboard keys, string-prefix waits) and the SQLite scenario checks selected states, not every transition. Statements below describe what is actually checked and the assumptions under which they hold.

## 1. Execution Tree & Convergence ($\mathcal{M}_{\text{tree}}$)

- **State**: `phase ∈ {Work, Check, ReportReady, Reporting, Complete}`, `round ≥ 1`, `active_root`, `tasks` (with `status ∈ {Queued, Running, Waiting, Approval, Done, Failed, Cancelled, Unknown}`), `operations` (with `state ∈ {Approval, Ready, Started, Done, Unknown, Cancelled}`), `check_attempts ∈ 0..=10`, and `continuation_node`.
- **Safety Invariants**:
  1. **One-way forward tree (`Inv_AcyclicTree`)**: A `handoff` closes its sender (`status = Done`) and creates `1..=64` children atomically within `(root, round)`. Across continuation rounds (`continue`), promoted continuation nodes satisfy `parent.root = root ∧ parent.round <= round ∧ parent.rowid < rowid`; descendants never target ancestors or siblings within a round, and each member takes at most one stage per `(root, round)`.
  2. **Convergence rule (`Inv_ConvergenceRule`)**: When all stages settle in `phase = Work` and verification passes (or is `not_requested`), a round with `1` terminal leaf settles directly at `Complete` with `continuation_node = Some(leaf_id)` (unless `outcome == Unknown`). A round with `≥ 2` terminal leaves transitions through `ReportReady -> Reporting -> Complete` via an internal `summarizer` node (`TurnKind::Reporter`) with zero workspace tools.
  3. **Authorized verification (`Inv_CheckAuthorization`, `Inv_AttemptCap`)**: When `check_command` is present, settlement into `Done` requires the latest `verify` operation on `(active_root, round)` matching the exact user-submitted command to be `Done` with `ok = true`. Each failed check dispatches a fresh forward repair stage (`status = Queued`) while `check_attempts < 10`, and stops cleanly into `Failed` at `check_attempts = 10`.
  4. **Unknown outcome absorption & cancellation fencing (`Inv_UnknownAbsorbing`, `Inv_NoReplay`)**: Any `Started` operation lost to crash (`recover()`) or active cancellation becomes `Unknown`, never replays, forces aggregate `outcome = Unknown` and `continuation_node = None`, and late worker/tool callbacks fail `discard_late_completion` without mutating settled or cancelled state.
- **Liveness / Termination (bounded abstraction)**: In the modeled transition system, every reachable non-terminal state has a finite path to `Complete`, checked by backward reachability in `formal_bfs_tree_check_repair_convergence_and_unknown_absorption`. Cancellation is excluded from the successor relation and checked separately by `formal_tree_cancellation_is_fenced_and_settles_all_stages`; it is not an unconditional edge from every state. The check assumes fair worker/approval progress and does not prove that production code terminates under crashes, unbounded retries, or a permanently parked approval. A `Complete` state is required to have terminal root/leaf stages.

## 2. Collaborative Whiteboard & Deadlock Freedom ($\mathcal{M}_{\text{wb}}$)

- **State**: Per-root `wb_seq ≥ 0`, `entries: Key ⇀ (kind, content, version, seq, status ∈ {Active, Resolved})`, and per-task wait columns `(wb_wait_key, wb_wait_seq)`.
- **Safety Invariants**:
  1. **Monotonic sequence & version CAS (`Inv_WbSerialized`)**: Every committed `set`, `append`, `resolve`, or `delete` increments `wb_seq` strictly and updates the affected entry `seq = wb_seq`. `set` and `delete` with `expected_version = Some(v)` succeed iff `v == current_version`, returning a structured `conflict: true` receipt otherwise without mutating `wb_seq` or `entries`. `append` and `resolve` are serialized read-modify-write operations inside the single-writer SQLite transaction, not lock-free operations. SQLite is the serialization point; this is not a proof of concurrent-history linearizability.
  2. **Waiter cleanup (`Inv_WaiterStatusConsistency`)**: Every terminal or running stage (`status ∈ {Running, Done, Failed, Cancelled, Unknown}`) satisfies `wb_wait_key = NULL ∧ wb_wait_seq = NULL`.
  3. **Deadlock freedom (`Inv_WbDeadlockFreedom`)**: At every quiescent step end in `phase = Work`, if any task in the active round is parked on `wb_wait` (`status = Waiting ∧ wb_wait_seq IS NOT NULL`), then at least one other potential writer remains unparked in `(root, round)`:
     $$\text{waiters}(r, R) \neq \varnothing \implies \text{other\_active}(r, R) > 0.$$
     If an operation leaves `other_active(r, R) == 0` (through self-parking, completion, failure, or subtree cancellation), `wake_wb_waiters` immediately unblocks all remaining waiters with `woke = "no_other_writers"`. A matching write, or a matching delete (which removes the entry but still advances `wb_seq`), wakes a waiter with `woke = "updated"`. `other_active` counts a sibling parked on human `approval` as a potential writer, so “deadlock-free” is a closed-worker-cycle property; a waiter can stay asleep while an approval is unresolved. `wb_wait` keys are prefix filters, while `wb_read` keys are exact; this asymmetry is intentional and documented.
  4. **Trust boundary (`Inv_UnverifiedBoard`)**: The `<= 4096`-byte digest injected at claim is transient (never persisted to `node_messages`), contains only entries with `seq > wb_seen_seq` (newest first when capped), and claiming does not advance the watermark. A batched `wb_read` acknowledges a covered unread range only after the complete, unfiltered receipt fits into the batch delivered to the worker. The Summarizer receives `whiteboard` entries strictly as unverified collaborative notes distinct from tool/verify receipts. Entries are capped at 64 KiB each and 1 MiB per root.

## 3. Auto-Compaction Termination ($\mathcal{M}_{\text{compact}}$)

- For persisted history length $L$, the production `compute_compaction_slice` accepts only $L \ge 4$ and starts with `head_keep = min(2, L - 2)`, then decrements `head_keep` by one when `head_keep > 1` and `history[head_keep - 1].role == "assistant"`. It starts with `tail_keep = 6` if $L \ge 10$, else `min(2, L - head_keep - 2)`, sets `mid_end = L - tail_keep`, and then decrements `tail_keep` and increases `mid_end` by one when `tail_keep > 0`, `history[mid_end - 1].role == "assistant"`, and `history[mid_end].role == "user"`. It returns `None` unless `mid_end > head_keep + 1`.
- Replacing `[head_keep..mid_end]` (length $d = \text{mid\_end} - \text{head\_keep} \ge 2$) with a single `checkpoint` message yields new length:
  $$L' = L - d + 1 \le L - 1 < L.$$
- **Bounded theorem (`Thm_CompactionTerminates`)**: For the production slice function, repeated compaction strictly decreases message count until reaching a fixed point. `formal_compaction_termination_and_progress_all_lengths` checks all role patterns for $L \le 12$ against `compute_compaction_slice` and one scripted real-Store path; the earlier 0..=2,000 sweep is a bounded arithmetic check, not a proof over all $L$. The fixed point is at most 9 messages for the tested lengths.

## 4. StreamBuffer Conservation & UTF-8 Safety ($\mathcal{M}_{\text{stream}}$)

- **State**: `(head, tail, omitted_bytes, omitted_lines)` with `HALF_OUTPUT = 65536` (`OUTPUT_LIMIT = 131072`).
- **Invariants (`Inv_StreamBoundedMemory`, `Inv_StreamConservation`, `Inv_StreamUtf8Safe`, `Inv_DrainBoundedBatch`)**:
  1. `head.len() ≤ HALF_OUTPUT ∧ tail.len() ≤ HALF_OUTPUT`, so live memory never exceeds `OUTPUT_LIMIT`.
  2. Before finish: `head.len() + omitted_bytes + tail.len() == total_bytes_pushed`.
  3. On `finish`: trimming incomplete trailing lead/continuation bytes from `head` and leading continuation bytes from `tail` preserves exact byte conservation `head_end + omitted_bytes + tail_len == total_bytes_pushed` and emits valid UTF-8 with zero replacement characters (`\u{FFFD}`) for the valid UTF-8 corpora and sampled chunk sizes exercised by `formal_stream_buffer_conservation_and_utf8_safety`. This is not a proof for every possible chunk split.
  4. `shell()` drains at most `64 KiB` (`DRAIN_BATCH_BYTES`) per stream per loop iteration (`DrainState::{Eof, WouldBlock, More}`). This bounds each drain call by construction, but the claim that a saturated writer cannot starve the sibling stream or `exited`/`timeout` checks is a design argument; the shell scheduling path is not exercised by the formal stream test (and depends on OS pipe behavior).

## 5. Boundary Contracts & Machine Verification Mapping

| Formal Module | Checked Properties | Checker / Evidence |
|---|---|---|
| $\mathcal{M}_{\text{wb}}$ | Bounded 2/3-leaf abstraction: serialized CAS, waiter cleanup, no closed-cycle deadlock, reachability | `formal_bfs_whiteboard_deadlock_freedom_and_cas_linearizability` |
| $\mathcal{M}_{\text{tree}}$ | Bounded abstraction: check auth, 10-attempt cap, 1/2-leaf convergence, `Unknown` absorption; separate cancellation fencing | `formal_bfs_tree_check_repair_convergence_and_unknown_absorption`, `formal_tree_cancellation_is_fenced_and_settles_all_stages` |
| SQLite integration | Selected invariants across ~21 scripted checkpoints; **not** every SQL transition and not a refinement proof | `formal_sqlite_integration_scripted_invariants` |
| $\mathcal{M}_{\text{compact}}$ | Production slice function over all role patterns $L \le 12$, plus one real-Store path; bounded progress | `formal_compaction_termination_and_progress_all_lengths` |
| $\mathcal{M}_{\text{stream}}$ | Sampled 128 KiB bound, byte conservation, UTF-8 boundary safety; drain scheduling is a design argument | `formal_stream_buffer_conservation_and_utf8_safety` |
| Decoder Boundary | Sampled op×kind matrix, clean/prose fences, `i64` bounds, redaction canary | `formal_action_decoder_fence_and_redaction_sampled` |
